# Проблема
Человек, который на онбординге указал дату рождения, режим сна, даты цикла
и сегодняшнее настроение, не видит ни одного следа этих ответов на Home и
Care — цифра «энергия дня», тексты дня и состояние Care считаются от
константы/демо-данных независимо от того, что он на самом деле ввёл.

# Доказательство
- Находка №5 (`findings.md`, статус «Открыта»): «ни одно из введённых на
  онбординге данных сейчас не отражается в том, что показывает Home/Care —
  всё захардкожено на дату/константу 42».
- `decisions.md` 2026-09-23: экран инсайта после даты рождения переведён на
  демо-текст (`USE_HOME_DEMO_INSIGHT = true`) именно потому что настоящий
  расчёт по формуле противоречил демо-кривым Home — то есть реальный расчёт
  (`lib/biorhythm.ts`) уже существует и работает, просто не подключён
  дальше как источник правды для Home.
- `backlog.md`, раздел «Онбординг»: флаг явно ждёт переключения «когда
  Главная перейдёт на настоящие расчёты».
- `product.md`: модель «энергия дня» (биоритм + сон + цикл) уже описана и
  согласована — это не гипотеза, а принятая формула, которую нужно
  подключить, не изобретать.

# Критерий успеха
На устройстве, без демо-флагов: для профиля, прошедшего онбординг с датой
рождения + хотя бы одним днём сна + (для женского профиля) датами цикла,
цифра «энергия дня» и текст дня на Home меняются при изменении любого из
этих трёх входов в рамках одной сессии — не фиксированы на 42 или на одном
зашитом тексте. Care получает то же число, а не отдельную независимую
константу. 0 экранов основного пути (Home, Care) с захардкоженным «42» или
активным demo-флагом.

Не измеряем в этом цикле удержание/конверсию — технически измеримо позже,
когда появится эксплуатация реальными пользователями, а не только её
собственный телефон.

# Не-цели
- Не строим в этом цикле постоянное хранение данных между перезапусками
  приложения и экран «Профиль» (анкета с правкой) — это отдельный, более
  крупный проект (см. `backlog.md`, разделы «Профиль», шифрование
  `expo-secure-store` из `decisions.md` 2026-09-18). Этот бриф — про то, что
  *уже собрано за сессию онбординга*, реально доходит до Home/Care; не про
  персистентность.
- Не строим движок персональных рекомендаций «почему предложено именно
  это» (следующий горизонт по `decisions.md` 2026-09-05, п. №5) — только
  подключаем число/тексты, которые уже существуют как формула.
- Не трогаем находку №8 (геймификация/память о практиках) — закрыта,
  решение не пересматривается.

## Что требует решения владельца прямо сейчас
1. **Активация находки №4 (wellbeing-safety).** Пока цифра была демо-кон­
   стантой 42, низкое значение никогда реально не показывалось живому
   человеку. Как только расчёт станет настоящим, однажды он честно выдаст
   низкое число. Нужно подтверждение `wellbeing-safety` и её «ок»: что
   именно должен увидеть человек в нижней части диапазона уже в *этом*
   цикле (хотя бы безопасный тон для одного плохого дня — полный триггер
   «N дней подряд» физически не посчитать без истории, которой пока нет).
   Без этого — не включать реальный расчёт на устройстве, которое увидят
   посторонние.
2. **Находка №2 (пустой/частичный профиль) неявно активируется этим же
   брифом.** Раньше отклонена как «преждевременно» (2026-09-05) ровно
   потому, что этого расчёта ещё не было. Теперь он появляется — нужно её
   решение: что видит человек, который пропустил дату рождения, сон или
   цикл (пропустил шаг / «заполнить позже») — пустое состояние, честная
   подпись «данных пока мало» или нейтральное дефолтное значение. Без
   этого решения реализация будет либо падать, либо тихо врать цифрой.
3. **Шаг цикла для тех, кто не может/не хочет указать даты** (беременность,
   менопауза, нерегулярный цикл, гормональные препараты) — открыто с
   2026-09-23 (`backlog.md`). Этот бриф впервые заставит этот пробел
   проявиться на практике: без решения эта часть профилей не получит
   цикл-компонент энергии вообще. Не блокирует весь бриф (можно просто
   считать энергию без цикл-компонента для них), но нужно её «да, так и
   оставляем на этот цикл» — чтобы не было похоже на забытый случай.
