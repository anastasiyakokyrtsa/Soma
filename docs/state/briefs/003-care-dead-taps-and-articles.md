# Проблема
На главном экране заботы (Care) половина интерактивных элементов —
навигационные чипы (Дыхание/Звуки природы/Медитации/Сказки/Музыка), 4 из
5 категорий чая, ссылки «Все статьи»/«Свет и внутренние часы»/«Паузы и
восстановление» — не реагируют на тап вообще, без какого-либо визуального
сигнала «пока не готово».

# Доказательство
- Находка №1 (`findings.md`): «тап не делает ничего... человек решит, что
  кнопка сломана, а не «пока не готово»». Статус на 2026-09-05 —
  «Отклонено», но причина отказа была процедурная, не по существу:
  «экран, которого касается находка, владелец сознательно ещё не
  проработала — преждевременно». Задача владельца от 2026-11-21 прямо
  просит построить недостающие экраны за этими тапами — то есть
  предпосылка прежнего отказа («рано») снята её же собственным новым
  запросом.
- `AnalyticsScreen.tsx` уже показывает рабочий образец честного решения
  для той же проблемы: 5 из 6 карточек помечены `available: false` и
  визуально приглушены — паттерн, который можно и нужно повторить на
  Care, а не изобретать новый.
- `backlog.md`, раздел «Статьи»: две статьи серии «Основы восстановления»
  («Свет и внутренние часы», «Паузы и восстановление») уже написаны
  целиком (`docs/content/статьи.md`), экран `ArticleWaterScreen` уже
  построен на переиспользуемой модели `ArticleBlock` — это дешёвая часть
  работы, текст и механизм уже есть, просто не собраны в экран.

# Критерий успеха
На экране Care 0 тапов без какой-либо реакции: каждый элемент либо ведёт
на реальный экран, либо показывает тот же визуальный паттерн «Скоро»
(приглушённый вид, без ложного ощущения сломанной кнопки), который уже
есть в `AnalyticsScreen`/`TeaCategoriesScreen`. Обе готовые статьи
открываются по ссылке и долистываются до конца на устройстве.

# Не-цели
- Не пишем новый контент для 4 недостроенных категорий чая и для чипов
  Звуки природы/Медитации/Сказки/Музыка в этом цикле — это отдельная по
  объёму работа (новые практики, новая проверка `claims-reviewer`/
  `wellbeing-safety` для каждой, не разметка экрана). Этот бриф закрывает
  *дыру в реакции интерфейса*, не обязывает написать весь контент
  приложения за один цикл — см. открытый вопрос №4 ниже, объём решает она.
- Дыхание уже работает (сквозной сценарий) — не трогаем.
- Не меняем формат статей (свайп-страницы) — уже решён и одобрен
  (`decisions.md` 2026-09-16), просто повторяем его для двух новых.

## Что требует решения владельца прямо сейчас
1. **Переоткрытие находки №1 требует её явного согласия, а не тихой
   отмены старого отказа.** Прежний отказ («преждевременно») был
   процедурным, не по содержанию — нужно зафиксировать в `decisions.md`
   её «да, беремся» именно сейчас, иначе выглядит как молчаливый пересмотр
   решения владельца без повода.
2. **Объём по каждой группе мёртвых тапов — заглушка «Скоро» или
   реальный контент сейчас?** Для 4 категорий чая и 4 чипов (Звуки
   природы/Медитации/Сказки/Музыка) это два разных по цене решения.
   Рекомендация product-lead: в этом цикле — честная заглушка
   («Скоро»), контент — отдельным циклом, потому что новый контент о
   регуляции состояния каждый раз требует прохода `claims-reviewer` и
   `wellbeing-safety`, а не только разметки экрана. Нужно её подтверждение
   или другой выбор объёма.
