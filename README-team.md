# Команда для приложения биоритмов, состояний и настроения

Полный набор: аудит существующих сценариев, затем продуктовые циклы.
iOS и Android, кроссплатформенное. Стадия — сценарии собраны, приложение
не построено.

## Состав команды: 17 ролей

### Аудит и качество
| Роль | По-русски | Решающее слово |
|---|---|---|
| `scenario-auditor` | Аудитор сценариев | Полнота и связность сценариев |
| `wellbeing-safety` | Безопасность состояния | Что продукт делает с человеком, которому плохо |
| `claims-reviewer` | Ревизор формулировок | Что продукт вправе утверждать |
| `privacy-reviewer` | Ревизор приватности | Допустимость сбора данных |
| `accessibility` | Доступность | Достаточность доступности |
| `audit-qa` | Контроль качества | Готово или нет |

### Продукт и проектирование
| Роль | По-русски | Решающее слово |
|---|---|---|
| `product-lead` | Продуктовый лид | Что делаем и в каком порядке |
| `ux-architect` | UX-архитектор | Модель взаимодействия и структура |
| `analyst` | Аналитик | Что считается доказательством |
| `habit-designer` | Специалист по удержанию | Механика привычки |
| `data-input-specialist` | Специалист по вводу данных | Способы ввода и их стоимость |

### Дизайн
| Роль | По-русски | Решающее слово |
|---|---|---|
| `ui-designer` | Дизайнер интерфейса | Визуальный язык и дизайн-система |
| `mobile-ux` | Мобильное взаимодействие | Досягаемость, жесты, прерывания |
| `platform-conformance` | Специалист по платформам | Где iOS и Android расходятся |

### Разработка
| Роль | По-русски | Решающее слово |
|---|---|---|
| `tech-lead` | Технический лид | Архитектура |
| `mobile-engineer` | Мобильный инженер | Реализация |

### Разрешение споров
| Роль | По-русски | Когда |
|---|---|---|
| `arbiter` | Арбитр | Только после двух кругов без согласия |

## Установка

Распакуй содержимое в корень репозитория, открой Claude Code и напиши:
«Прочитай `SETUP.md` и выполни». Он разложит файлы, проверит подключение
и скажет, чего не хватает для запуска.

## Порядок работы

**Фаза 0 — аудит.** `/scenario-audit`. Начинается с изучения продукта:
команда описывает его своими словами, вы подтверждаете. Только потом находки.
Результат — отчёт, не правки.

**Разбор находок.** `product-lead` по каждой принимает решение: чиним сейчас,
позже, не чиним. Отказ фиксируется с причиной. Блокеры и находки
`wellbeing-safety` не отклоняются без вашего согласия.

**Фаза 1 и далее — продуктовые циклы.** `/loop-start`, затем `/loop-review`.
Бриф → спека → дизайн → разработка → проверка.

**Правки сценариев без полного цикла** — `/scenario-fix`.

## Правила, делающие команду самостоятельной

- Одна зона решения у каждой роли, в чужую приносят возражение, не решение
- Контракты приёмки с правом отказа без доработки
- Право блокировки по своей теме
- Лимит два круга правок, дальше арбитр
- Общий источник правды в файлах, не в переписке

## Приоритет этого продукта

Безопасность работы с состоянием → барьер ввода → первые три дня → возврат
после пропуска → ценность вывода → и только потом красота экранов.

`wellbeing-safety` проверяет любой сценарий, касающийся настроения, состояния
или их регуляции. Его слово решающее, и это записано в контрактах передачи.

## Перед запуском заполнить

`docs/state/product.md`: природа биоритмов в продукте (классическая теория
23/28/33 или циркадные ритмы), что входит в регуляцию состояния и на чём
основано, модель монетизации. И положить сценарии в `docs/state/scenarios/`.
